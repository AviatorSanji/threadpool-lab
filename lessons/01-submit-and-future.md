# 第一课：任务、线程和等待结果

这一课只弄清楚四件事：任务对象何时创建，谁调用它的 call，如何交给池执行，以及请求线程何时能拿到结果。

## 1. 先预测，再运行

```bash
bash run.sh serial
bash run.sh pool 2
```

输出四列：事件序号、相对耗时、当前线程名、事件内容。

串行模式下，main 直接调用每个任务的 call。池模式下，main 先提交全部任务，然后在 get 中等待，工作线程执行任务。main 在这里代表处理请求的线程，不代表服务里的所有请求只有一个主线程。

观察以下细节：

- 创建任务的那行输出后，还没有 START；构造 Callable 对象本身不执行任务。
- SUBMIT 在 main；START 在 calc-worker-*。工作线程可以在 submit 返回之前开始执行，因此 START 与 ACCEPT 的相对次序不固定。
- 只有两个工作线程，却有三个任务。同一工作线程可以执行完一个任务再执行下一个。
- main 可能正在 get(A)，B 和 C 仍继续工作。get 阻塞的是调用它的线程。
- GOT 按 A、B、C 排列，因为循环按此顺序 get；END 的顺序由执行情况决定，不能据此认为结果顺序等于完成顺序。
- 总价格始终应为 27000 分。不要把一次运行的毫秒数当成固定保证。

通常会看到 B 完成后其工作线程开始 C，A 最后完成；操作系统调度可能改变观察到的时序。当前示例没有用协调工具强制指定完成顺序。

## 2. 对着代码走一遍 A

1. `new PriceTask("A", ...)` 创建任务对象。
2. `pool.submit(task)` 提交这个对象，得到 Future。
3. JDK 在线程池内部将 Callable 包装成可运行且可保存结果的任务；以后会具体跟到 FutureTask。
4. 工作线程执行内部任务，进而调用 `PriceTask.call()`。
5. `call()` 返回价格，内部任务记录完成状态和结果。
6. main 的 `future.get()` 取得价格；若未完成便等待，若已经完成则直接读取。
7. main 汇总价格；演示程序结束前关闭池。

END 表示 call 即将返回，还不是 Future 已经完成的精确标记；真正保存结果发生在 call 返回之后。

## 3. 你来改：只改等待的位置

在 `runInPool` 中临时把提交循环改成如下形式，并移除原来的取结果循环：

```java
int total = 0;
for (PriceTask task : tasks) {
    Future<Integer> future = pool.submit(task);
    total += future.get();
}
return total;
```

先预测，再运行。观察 B 是否要等 A 完成后才提交。理解后恢复“先全部提交，再逐个 get”的版本。

这个实验解释一个常见误区：使用了线程池，并不代表写出的程序就一定让多个任务并发运行。
